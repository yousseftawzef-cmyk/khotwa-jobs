# خُطوة

منصة وظائف عربية لخريجي المعهد العالي للإدارة. الواجهة متصلة بخادم Flask وقاعدة SQLite؛ الوظائف التجريبية تُضاف تلقائيًا أول مرة، وطلبات التقديم تُحفظ في قاعدة البيانات.

يوجد نوعان للحسابات:

- **باحث عن عمل:** يسجّل بالبريد وكلمة مرور وبيانات الملف الشخصي، ويتصفح الوظائف ويقدّم عليها. التقديم يتطلب الدخول، ويُسجل بحساب الباحث ويظهر للشركة صاحبة الوظيفة فقط.
- **شركة / صاحب عمل:** يسجّل حسابًا وملف شركة، وينشر الوظائف التي تظهر مباشرة، ويتابع الوظائف وطلبات التقديم والسير الذاتية الخاصة بوظائفه.

## التشغيل محليًا على Windows

1. ثبّت Python 3.10 أو أحدث.
2. افتح PowerShell داخل مجلد المشروع.
3. ثبّت المتطلبات:

   ```powershell
   python -m venv .venv
   .\.venv\Scripts\Activate.ps1
   python -m pip install -r requirements.txt
   ```

4. شغّل الخادم:

   ```powershell
   python app.py
   ```

5. افتح `http://127.0.0.1:8000`.

ينشئ التطبيق قاعدة البيانات تلقائيًا في `instance/step.db` ويحفظ السير الذاتية في `instance/uploads`. لا تفتح `index.html` مباشرة؛ يجب تشغيل التطبيق حتى تعمل الوظائف والتقديم.

## النشر على الإنترنت

- يحتوي `render.yaml` على إعداد نشر تجريبي مجاني على Render مع HTTPS وفحص صحة التطبيق وإنشاء مفتاح جلسة ثابت للخدمة.
- للنشر:
  1. أنشئ مستودع GitHub **عامًا** وارفع ملفات المشروع الأساسية، ومنها `app.py` و`index.html` و`scr.js` و`s.css` و`requirements.txt` و`render.yaml` و`Procfile` و`README.md`.
  2. لا ترفع مجلد `instance` أو ملفات `.env` أو `.venv`؛ فهي بيانات محلية ومستثناة في `.gitignore`.
  3. في Render اختر **New > Blueprint**، اربط مستودع GitHub، ثم أنشئ الخدمة من إعداد `render.yaml`.
  4. بعد نجاح النشر، استخدم رابط الخدمة الظاهر في لوحة Render لفتح الموقع من الهاتف أو الكمبيوتر.
- **الخطة المجانية للتجربة فقط:** قد يتوقف التطبيق عند عدم الاستخدام، وقاعدة SQLite والسير الذاتية محفوظة على مساحة مؤقتة؛ قد تضيع الحسابات والوظائف والطلبات والملفات عند إعادة التشغيل أو إعادة النشر. لا تستخدمها لاستقبال بيانات حقيقية.
- لاستقبال بيانات حقيقية، استخدم استضافة بقرص دائم واضبط `DATABASE_PATH` و`UPLOAD_DIR` داخل ذلك القرص، وخذ نسخًا احتياطية. استخدم HTTPS، وقيّد الوصول للقرص وقاعدة البيانات، ولا تعرض السير الذاتية للعامة.
- لوحة مسؤول لإدارة الحسابات والتحقق من الشركات غير متوفرة. التسجيل لا يتضمن تأكيد البريد أو استعادة كلمة المرور، ونشر الشركات فوري؛ راجع الشركات والوظائف يدويًا قبل اعتماد المنصة للاستخدام العام.
- SQLite مناسب لإطلاق صغير على خادم واحد بقرص دائم. عند زيادة الزيارات أو تشغيل أكثر من نسخة، انقل البيانات إلى PostgreSQL وتخزين ملفات خاص.

## قاعدة البيانات

- `companies`: الشركات وبيانات عرضها.
- `jobs`: الوظائف وتصنيفها وموقعها وحالتها.
- `applications`: طلبات التقديم المرتبطة بالوظائف واسم المتقدم وبريده وهاتفه وحالة الطلب.
- `users`: بيانات تسجيل الدخول والدور، مع تخزين كلمات المرور كـ hashes لا كنص صريح.
- `seeker_profiles`: محافظة الباحث وتخصصه واسم ملف سيرته الذاتية المخزن.
- ملفات السير الذاتية لا تُخزن داخل SQLite؛ تحفظ بأسماء عشوائية في مجلد خاص غير معروض كملفات ثابتة.

الوظائف التسع المضافة تلقائيًا بيانات تجريبية. توجد لوحة حساب للشركات لإدارة عرض وظائفها وطلبات التقديم عليها. إدارة عامة للمنصة لمراجعة الحسابات والشركات ما زالت تحتاج لوحة مسؤول منفصلة.

قبل الإطلاق العام، أضف لوحة دخول وصلاحيات للمسؤولين، وحدًّا للطلبات الآلية، وسياسة خصوصية تحدد مدة الاحتفاظ ببيانات المتقدمين وآلية حذفها. لا تُرسل طلبات حقيقية قبل استبدال الوظائف التجريبية والتحقق من أصحابها.
